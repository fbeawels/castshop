# FedexRequestQuotesImpl.java

## Review

## 1. Summary

**Purpose**  
`FedexRequestQuotesImpl` is a service component that retrieves real‑time FedEx shipping quotes via the FedEx Rate API (SOAP).  
Given a set of shipping packages, a customer, a merchant store, and configuration data, it builds a `RateRequest`, sends it to FedEx, parses the response, and returns a collection of `ShippingOption` objects that can be displayed to the shopper.

**Key components**

| Component | Role |
|-----------|------|
| `getQuote()` | Main entry point – builds the SOAP request, invokes the service, and processes the reply. |
| `writeServiceOutput()` | Converts the `RateReply` into a list of `ShippingOption` instances. |
| `createClientDetail()` / `createWebAuthenticationDetail()` | Construct FedEx authentication objects from configuration. |
| `getServiceType()` / `getPackagingType()` | Translate string identifiers into FedEx enums. |
| `printNotifications()` | Logs FedEx notifications (warnings, errors, etc.). |
| `isResponseOk()` | Helper to decide whether a notification severity indicates a successful response. |

**Design patterns / frameworks**

* **SOAP/Axis** – the FedEx stubs are generated by Apache Axis.  
* **Factory / ServiceLocator** – `RateServiceLocator` is used to obtain a `RatePortType` for the call.  
* **Utility / Helper classes** – many internal utilities (`CountryUtil`, `CurrencyUtil`, `DateUtil`, etc.) are leveraged.  
* **Logging** – Log4j is used for runtime diagnostics.  
* **Configuration abstraction** – `ConfigurationResponse` and `IntegrationKeys` provide a loosely coupled way to read credentials and other settings.

## 2. Detailed Description

### 2.1 Flow of Execution

1. **Parameter intake** – The caller supplies carrier code, delivery type, module name, collection of `PackageDetail`, order total, merchant configuration, store, customer, and locale.  
2. **Request construction** –  
   * A `RateRequest` is created and populated with client credentials (`ClientDetail`), authentication (`WebAuthenticationDetail`), transaction details, and a version identifier.  
   * A `RequestedShipment` is built: ship timestamp, drop‑off type, service type (if not all rates), packaging type, shipper and recipient addresses (derived from `MerchantStore` and `Customer`), payment type, and the list of packages.  
   * Each package is converted into a `RequestedPackage` with weight, dimensions, and special services.  
   * The request also includes the rate request type (`ACCOUNT`) and the package detail type (`INDIVIDUAL_PACKAGES`).  
3. **Endpoint resolution** – The service endpoint (host, protocol, port, URL) is obtained from a central module service (`CoreModuleService`).  
4. **SOAP call** – A `RateServiceLocator` is configured with the endpoint, and the `getRates()` operation is invoked.  
5. **Response handling** –  
   * If the highest severity in the reply is *OK*, the response is passed to `writeServiceOutput()` to convert it into `ShippingOption` objects.  
   * All FedEx notifications are logged via `printNotifications()`.  
6. **Return** – The collection of shipping options (or `null` if the service was misconfigured) is returned.

### 2.2 Assumptions & Constraints

* The method assumes that the FedEx credentials (`accountNumber`, `meterNumber`, `key`, `password`) are present in the configuration; missing values throw a generic `Exception`.  
* It assumes that the `CountryUtil` and `RefCache` services are fully populated; missing zones or countries can lead to NPEs.  
* Only *ACCOUNT* rate request type is used; if the customer is not a FedEx account holder, the call will likely fail.  
* The implementation relies heavily on string literals for service names, packaging codes, and configuration keys; any change in FedEx API or internal naming will break the code.  
* The code is **not thread safe** because it uses instance fields only for the logger.  
* Error handling is coarse: generic exceptions are caught and logged, but the caller receives `null` without a clear reason.  

### 2.3 Architecture & Design Choices

* **Separation of concerns** – The class focuses on quote retrieval; other responsibilities (e.g., persistence, UI formatting) are delegated elsewhere.  
* **Utility-driven** – Helper methods (`getServiceType()`, `getPackagingType()`) reduce duplication but use long if‑else chains.  
* **No builder pattern** – The SOAP objects are assembled manually, leading to verbose code.  
* **Hard‑coded constants** – Many string values are hard‑coded rather than defined in an enum or property file.

## 5. Additional Notes & Recommendations

### 5.1 Code Quality Issues

| Issue | Impact | Suggested Fix |
|-------|--------|---------------|
| **Hard‑coded strings** (`"STANDARD_OVERNIGHT"`, `"FEDEX_1_DAY_FREIGHT"`, `"1"`, `"2"`, …) | Brittle; changes in FedEx API or configuration break the code. | Replace with enums or constants; consider a mapping table loaded from a property file. |
| **Long if‑else chains** in `getServiceType()` & `getPackagingType()` | Hard to maintain; no compile‑time safety. | Use a `Map<String, ServiceType>` or `Enum.valueOf()` with proper naming. |
| **Missing generics** (e.g., `Collection returnColl = null;`) | Raw types increase risk of `ClassCastException`. | Use generic collections (`Collection<ShippingOption>`, `Map<Integer, Country>`, etc.). |
| **Null checks** are sparse (e.g., `zone == null` check incorrectly uses `zone` instead of `customerZone`). | Possible NPEs. | Add defensive checks, validate input arguments. |
| **Error handling**: generic `Exception` thrown and swallowed; caller receives `null`. | Loss of diagnostic information. | Throw a custom checked exception (`FedExQuoteException`) or return a detailed error object. |
| **Thread safety**: None of the internal mutable state is protected, but the class is stateless aside from the logger, so it is effectively thread safe. | N/A | None needed, but documenting that the class is thread‑safe would be helpful. |
| **Hardcoded `CurrencyUtil.displayFormatedAmountWithCurrency`** usage: amount formatting logic is duplicated. | Inconsistency if currency formatting rules change. | Centralize formatting in a dedicated service. |
| **Unused parameters**: `orderTotal` is never used. | Clutter. | Remove if not needed, or incorporate into logic if relevant. |
| **Magic `int` constants** (`displayQuoteDeliveryTime` passed to `writeServiceOutput()`) | Hard to understand. | Use enum for display type, pass the enum itself. |

### 5.2 Design Improvements

1. **Builder / Fluent API** – Create a small wrapper that builds the complex `RateRequest` using a fluent builder. This would reduce boilerplate and make the construction logic easier to read.  
2. **Configuration abstraction** – Use dependency injection (Spring or CDI) to inject `ConfigurationResponse` and other services; this makes unit testing easier.  
3. **Unit tests** – The current class is difficult to test because it performs real SOAP calls. Extract the SOAP invocation into a separate interface (`FedExRateService`) that can be mocked.  
4. **Logging** – Use structured logs (e.g., `log.info("Obtaining FedEx rates for storeId={}", store.getMerchantId());`).  
5. **Notification handling** – Instead of simply printing, expose the notifications to the UI layer so shoppers can see warnings (e.g., *“Delivery date not guaranteed”*).  
6. **Performance** – The code rebuilds the `Country` & `Zone` cache every call. If performance is critical, consider caching the endpoint and reusing the service locator.  

### 5.3 Potential Enhancements

* **Support for other FedEx APIs** – If the store is not a FedEx account holder, switch to the `WEB` rate request type.  
* **Internationalization** – Use `ResourceBundle` for mapping labels instead of `ShippingUtil.buildServiceMap()`.  
* **Retry logic** – Add exponential back‑off for transient network failures.  
* **Async support** – Wrap the SOAP call in a `CompletableFuture` for non‑blocking calls in modern UI frameworks.  

---

### Bottom Line

`FedexRequestQuotesImpl` is a functional, if somewhat dated, implementation that bridges the internal SalesManager domain with the FedEx Rate API.  
Its current design is adequate for a small, single‑threaded service but would benefit from modern Java idioms, stricter type safety, better configuration management, and clearer error reporting. Implementing the above recommendations would make the class more maintainable, robust, and testable.

	private ServiceType getServiceType(String serviceTypeId) {

		if (StringUtils.isBlank(serviceTypeId)) {
			log
					.warn("ServiceType is blank or null, will return standard overnight");
			return ServiceType.STANDARD_OVERNIGHT;
		}

		ServiceType sType = null;

		if (serviceTypeId.equals("STANDARD_OVERNIGHT")) {
			sType = ServiceType.STANDARD_OVERNIGHT;
		} else if (serviceTypeId.equals("FEDEX_1_DAY_FREIGHT")) {
			sType = ServiceType.FEDEX_1_DAY_FREIGHT;
		} else if (serviceTypeId.equals("FEDEX_2_DAY_FREIGHT")) {
			sType = ServiceType.FEDEX_2_DAY_FREIGHT;
		} else if (serviceTypeId.equals("FEDEX_3_DAY_FREIGHT")) {
			sType = ServiceType.FEDEX_3_DAY_FREIGHT;
		} else if (serviceTypeId.equals("FEDEX_2_DAY")) {
			sType = ServiceType.FEDEX_2_DAY;
		} else if (serviceTypeId.equals("FEDEX_EXPRESS_SAVER")) {
			sType = ServiceType.FEDEX_EXPRESS_SAVER;
		} else if (serviceTypeId.equals("FEDEX_GROUND")) {
			sType = ServiceType.FEDEX_GROUND;
		} else if (serviceTypeId.equals("FIRST_OVERNIGHT")) {
			sType = ServiceType.FIRST_OVERNIGHT;
		} else if (serviceTypeId.equals("GROUND_HOME_DELIVERY")) {
			sType = ServiceType.GROUND_HOME_DELIVERY;
		} else if (serviceTypeId.equals("INTERNATIONAL_ECONOMY")) {
			sType = ServiceType.INTERNATIONAL_ECONOMY;
		} else if (serviceTypeId.equals("INTERNATIONAL_ECONOMY_FREIGHT")) {
			sType = ServiceType.INTERNATIONAL_ECONOMY_FREIGHT;
		} else if (serviceTypeId.equals("INTERNATIONAL_FIRST")) {
			sType = ServiceType.INTERNATIONAL_FIRST;
		} else if (serviceTypeId.equals("INTERNATIONAL_PRIORITY")) {
			sType = ServiceType.INTERNATIONAL_PRIORITY;
		} else if (serviceTypeId.equals("INTERNATIONAL_PRIORITY_FREIGHT")) {
			sType = ServiceType.INTERNATIONAL_PRIORITY_FREIGHT;
		} else if (serviceTypeId.equals("PRIORITY_OVERNIGHT")) {
			sType = ServiceType.PRIORITY_OVERNIGHT;
		} else {
			sType = ServiceType.STANDARD_OVERNIGHT;
		}

		return sType;

	}

	private PackagingType getPackagingType(String optionId) {

		if (StringUtils.isBlank(optionId)) {
			log
					.warn("PackageOption is blank or null, will return YourPackaging");
			return PackagingType.YOUR_PACKAGING;

		PackagingType pType = null;

		if (optionId.equals("1")) {
			pType = PackagingType.FEDEX_TUBE;
		} else if (optionId.equals("2")) {
			pType = PackagingType.FEDEX_10KG_BOX;
		} else if (optionId.equals("3")) {
			pType = PackagingType.FEDEX_25KG_BOX;
		} else if (optionId.equals("4")) {
			pType = PackagingType.FEDEX_BOX;
		} else if (optionId.equals("5")) {
			pType = PackagingType.FEDEX_PAK;
		} else if (optionId.equals("6")) {
			pType = PackagingType.FEDEX_ENVELOPE;
		} else if (optionId.equals("7")) {
			pType = PackagingType.YOUR_PACKAGING;
		} else {
			pType = PackagingType.YOUR_PACKAGING;
		}

		return pType;

	}

		request.setRequestedShipment(requestedShipment);

		//
		try {
			// Initialize the service
			RateServiceLocator service;
			RatePortType p;
			//
			service = new RateServiceLocator();

			// updateEndPoint(service);
			String endPointUrl = protocol + "://" + host + ":" + port + url;

			service.setRateServicePortEndpointAddress(endPointUrl);

			p = service.getRateServicePort();
			// This is the call to the web service passing in a RateRequest and
			// returning a RateReply
			RateReply reply = p.getRates(request); // Service call
			if (isResponseOk(reply.getHighestSeverity())) {
				returnColl = writeServiceOutput(displayQuoteDeliveryTime,
						reply, module, carrier, locale, store.getCurrency());
			}
			printNotifications(store, reply.getNotifications());

		} catch (RuntimeException e) {
			e.printStackTrace();
			log.error(e);
		} catch (Exception ex) {
			log.error(ex);
		}

		return returnColl;
	}

	private ClientDetail createClientDetail(String carrier,
			ConfigurationResponse vo) throws Exception {
		ClientDetail clientDetail = new ClientDetail();

		IntegrationKeys keys = (IntegrationKeys) vo.getConfiguration(carrier
				+ "-keys");

		String accountNumber = keys.getUserid();
		String meterNumber = keys.getKey2();

		//
		// See if the accountNumber and meterNumber properties are set,
		// if set use those values, otherwise default them to "XXX"
		//
		if (accountNumber == null) {
			throw new Exception("FedexQuotesImpl, missing accountNumber");
		}
		if (meterNumber == null) {
			throw new Exception("FedexQuotesImpl, missing meterNumber");
		}
		clientDetail.setAccountNumber(accountNumber);
		clientDetail.setMeterNumber(meterNumber);
		return clientDetail;
	}

	private WebAuthenticationDetail createWebAuthenticationDetail(
			String carrier, ConfigurationResponse vo) throws Exception {

		IntegrationKeys keys = (IntegrationKeys) vo.getConfiguration(carrier
				+ "-keys");

		WebAuthenticationCredential wac = new WebAuthenticationCredential();

		String key = keys.getKey1();
		String password = keys.getPassword();

		//
		// See if the key and password properties are set,
		// if set use those values, otherwise default them to "XXX"
		//
		if (key == null) {
			throw new Exception("FedexQuotesImpl, missing key");
		}
		if (password == null) {
			throw new Exception("FedexQuotesImpl, missing password");
		}
		wac.setKey(key);
		wac.setPassword(password);
		return new WebAuthenticationDetail(wac);
	}

	private void printNotifications(MerchantStore store,
			Notification[] notifications) {
		if (notifications == null || notifications.length == 0) {
			return;
		}
		for (int i = 0; i < notifications.length; i++) {
			Notification n = notifications[i];

			NotificationSeverityType notificationSeverityType = n.getSeverity();
			// if(notificationSeverityType.equals(NotificationSeverityType.WARNING)||
			// notificationSeverityType.equals(NotificationSeverityType.NOTE) )
			// {

			LogMerchantUtil.log(store.getMerchantId(),
					"Notification from Fedex Code=[" + n.getCode()
							+ "] message[" + n.getMessage() + "]");

			if (notificationSeverityType.equals(NotificationSeverityType.ERROR)
					|| notificationSeverityType
							.equals(NotificationSeverityType.FAILURE)) {
				log.error("FEDEX  Severity: "
						+ (notificationSeverityType == null ? "null"
								: notificationSeverityType.getValue()));
				log.error("FEDEX  Code: " + n.getCode());
				log.error("FEDEX  Message: " + n.getMessage());
				log.error("FEDEX  Source: " + n.getSource());
			}

			// }
		}
	}

	private boolean isResponseOk(
			NotificationSeverityType notificationSeverityType) {
		if (notificationSeverityType == null) {
			return false;
		}
		if (notificationSeverityType.equals(NotificationSeverityType.WARNING)
				|| notificationSeverityType
						.equals(NotificationSeverityType.NOTE)
				|| notificationSeverityType
						.equals(NotificationSeverityType.SUCCESS)) {
			return true;
		}
		return false;
	}
