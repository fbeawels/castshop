## 5. Additional Notes & Recommendations  

### 5.1. Missing `equals()` and `hashCode()`  
Hibernate expects composite key classes to override `equals()` and `hashCode()` so that key instances can be compared and used in collections or caching. The absence of these methods will lead to incorrect behaviour (e.g., duplicate rows, failures in session caching).  
**Suggested implementation:**
```java

    if (this == o) return true;
    if (!(o instanceof MerchantId)) return false;
    MerchantId that = (MerchantId) o;
    return merchantId == that.merchantId &&

}

@Override

}
```

### 5.2. Mutability & Immutability  
If the key is used in hashed collections, mutating `dateAdded` after insertion will corrupt the hash. Consider making the class immutable: declare fields `final`, remove setters, and provide only a constructor.

`java.util.Date` stores milliseconds since epoch, but its `toString()` representation is time‑zone dependent. If `dateAdded` is only used as a part of the key, storing it as a `Timestamp` or `Instant` may be clearer.
